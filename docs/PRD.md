# PRD: Widget Lab（Flutter Widget カタログアプリ）

> **要約**
> - 結論: Flutter の公式 Widget カタログに載る Widget を全ジャンル収録し、プロパティを切り替えて触り、付けた／付けないを並べて比べられる iOS / Android アプリを作る
> - 影響: 新しいリポジトリ `widget-lab`（public）を ~/dev に作る。収益は狙わず、ストアに出せるなら出す
> - お願い: なし（2026-10-28 承認済み）

## 概要

Flutter から離れたあとでも、Widget の挙動を数十秒で思い出せる手元の辞書アプリ。Widget ごとに公式の要約を載せ、プロパティを実際に変えて触り、付けた場合と付けない場合を並べて比べられるようにする。

## ユーザーストーリー

- Flutter に久しぶりに戻った開発者として、Widget のプロパティを変えてその場で見た目の変化を確かめたい。なぜならドキュメントを読むより早く思い出せるから。
- Flutter に久しぶりに戻った開発者として、あるプロパティを付けた場合と付けない場合を並べて見たい。なぜなら何が変わるのかを見落とさずに分かるから。
- Flutter に久しぶりに戻った開発者として、`InheritedWidget` のような見た目を持たない Widget の働きを目で確かめたい。なぜなら説明を読むだけでは、いつ再ビルドされるかが分かりにくいから。
- Flutter に久しぶりに戻った開発者として、今の設定を再現するコードをコピーしたい。なぜならそのまま自分のコードで試せるから。
- Flutter に久しぶりに戻った開発者として、Widget の名前で探したい。なぜなら名前を覚えているときは一覧をたどるより早いから。

## 機能要件

### 一覧（ジャンル別）

- 公式の Widget カタログ（flutter.dev）のジャンル分けに沿って、ジャンル → Widget の順にたどれる
- 収録の範囲は、公式カタログの全ジャンルに載る全 Widget。`InheritedWidget` などの見た目を持たない Widget も含む
- 各 Widget に、ジャンル・名前・一行の要約を表示する

### 検索

- Widget 名の部分一致で絞り込める（大文字・小文字を区別しない）

### 詳細: 説明

- 公式 API ドキュメントをもとにした短い要約（日本語）と、公式ページへのリンクを表示する
- 操作できる各プロパティに、一言の説明（日本語）を付ける

### 詳細: プレイグラウンド（A）

- プレビューの下に、プロパティの操作パネルを置く
- プロパティごとに ON/OFF（付ける／付けない）を切り替えられる。OFF は「そのプロパティを指定しない（既定値）」の状態
- ON のときは値を変えられる。型に合わせた操作部品を使う（数値: スライダー、真偽: スイッチ、enum: 選択、色: パレット、など）
- 複数のプロパティを同時に変えられ、プレビューにその場で反映される
- 初期状態に戻すボタンがある

### 詳細: 比較（B）

- 「比較する」を押すと、選んだプロパティを付けた状態と付けない状態のプレビューを上下に並べて表示する
- 比較のとき、それ以外のプロパティの設定は両方に同じく反映される

### 見た目を持たない Widget の可視化

- 再ビルドの回数、値が届く範囲、イベントのログなどを画面に出し、その Widget を使った場合と使わない場合を比べられる
- Widget ごとの見せ方は設計の段で決める

### コードの表示とコピー

- 今の設定を再現する Dart のコードを表示する
- コードをクリップボードにコピーできる

### デモの組み立て

- 各 Widget のデモは、プロパティの定義（名前・型・既定値・操作部品・説明）のデータから組み立てる。Widget を1つ足す手間を小さくするため

## 非機能要件

- パフォーマンス: プロパティを変えたら、プレビューへの反映は体感で遅れない（目安 100ms 以内）
- オフライン: 全機能がオフラインで使える（公式ページへのリンクを開くときだけ通信する）
- アクセシビリティ: アプリ自体の UI は WCAG 2.2 AA を目安にする（コントラスト・タップ領域・スクリーンリーダーのラベル）。収録する Widget の見た目は公式のまま
- セキュリティ: 個人のデータ・アカウント・外部の API は扱わない。リポジトリは public のため、署名鍵・ストアの認証情報・`.env` などをコミットしない

## 受け入れ条件

- [ ] 公式 Widget カタログの全ジャンルが一覧に表示される
- [ ] 公式 Widget カタログに載る全 Widget が、どれかのジャンルの下に表示される
- [ ] 名前の一部（例: `pad`）を入れると、`Padding` など名前に含む Widget だけが残る
- [ ] 詳細で、プロパティを OFF にするとプレビューがそのプロパティの既定値の見た目になる
- [ ] 詳細で、数値のプロパティのスライダーを動かすとプレビューがその値で描き直される
- [ ] 詳細で、2つ以上のプロパティを変えると、両方がプレビューに反映される
- [ ] 「比較する」を押すと、付けた状態と付けない状態のプレビューが上下に並ぶ
- [ ] 初期状態に戻すと、全プロパティが最初の値になる
- [ ] `InheritedWidget` の詳細で、再ビルドされた Widget とその回数が画面に表示される
- [ ] コードの表示に、今の設定を再現する Dart のコードが出る
- [ ] コピーを押すと、表示中のコードがクリップボードに入る
- [ ] 機内モードでも、一覧・検索・詳細・比較・コードの表示が使える
- [ ] 公式ページへのリンクを押すと、該当の API ドキュメントがブラウザで開く
- [ ] iOS 26.0 の端末と Android 15（API 35）の端末で起動し、上の条件を満たす

## 技術的考慮事項

### 影響レイヤー

新規のアプリなので、全レイヤーを新しく作る。構成は flutter-project-setup で決める。

- Presentation/View: 一覧・検索・詳細（プレビュー・操作パネル・比較・コード）
- Business Logic/Feature: プロパティの状態、比較の状態、コードの生成
- Data/Repository: Widget とプロパティの定義（アプリに同梱する。通信しない）
- Domain/Model: Widget・ジャンル・プロパティ定義・プロパティの型

### 主要な技術的決定

- スタック: Flutter / Dart。Flutter と依存は生成時の最新の安定版
- 対象 OS: iOS / Android。最低の版は iOS 26.0 / Android minSdk 35（otayori にそろえる）
- org: `jp.nimi`（otayori にそろえる）
- アプリ名: Widget Lab。リポジトリ: `widget-lab`（GitHub public、~/dev/widget-lab）
- アプリ自体の UI の設計言語: Material 3（収録する Material の部品となじみ、iOS / Android で同じ見た目にできるため）
- 言語: 日本語のみ。Widget 名・プロパティ名は英語のまま
- デモはプロパティの定義のデータから組み立てる（全部を収録するため、1つ足す手間を小さくする）
- ダークモード: 対応する。理由: Material 3 のテーマで低コストに対応でき、収録する Widget のダークテーマでの見え方も確かめられる
- タブレット・横向き: スマホの縦向きを主にし、タブレットはスマホと同じ1カラムで表示する。理由: 対象外にすると審査の指摘を受けやすく、2カラム化は後から足せる
- Cupertino の Widget を Android で表示するとき（Material を iOS で表示するときも）: OS に関わらずそのまま表示する。理由: カタログとして見た目を確かめるのが目的のため
