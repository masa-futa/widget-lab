# cb_dtl 詳細画面

> **要約**
> - 結論: 上にプレビューとコードの帯、その下にプロパティのチップの列、下半分に選んだ1つを大きく触る編集パネルを置く。比べるはプレビューを左右に分ける
> - 影響: アプリのコア（プレイグラウンドと比較）。タブ（操作・説明・コード）はやめ、説明はシート、コードは帯と全文のシートにした（ADR-0004）
> - お願い: 項目と文言の確認

## 概要

| ID | 日本語名 | 英語名 | 画面種別 | 実装種別 | 備考 |
|-|-|-|-|-|-|
| cb_dtl | 詳細画面 | DetailScreen | スクリーン（シート: 説明・コードの全文） | ネイティブ | ca_lst・cc_gnr から Push |

1つの Widget について、プロパティを1つずつ選んで値を変え、その場で見た目とコードの変化を確かめ、付けた場合と付けない場合を左右に並べて比べ、今の設定のコードを持ち帰る。

部品は Material 3 の標準（`AppBar`・`Switch`・`Slider`・`SegmentedButton` / `DropdownMenu`・`ChoiceChip`・`IconButton`・`FilledButton.tonal`・`TextButton`・`SnackBar`・`showModalBottomSheet`）。仲間のタブは自前の横並び（押せる範囲 48×48）。色見本・Alignment の 3×3・比較の仕切り・コードの帯は標準の部品がないので、土台の値で自前に作る。

主な操作（チップを選ぶ・値を変える）は画面の下半分にあり、親指で届く。プレビューとコードの帯は操作しても隠れない。

## 状態変化

```mermaid
flowchart TB
    initial["初期状態<br/>最初の ON のプロパティを選択<br/>初期状態に戻す 非活性"]
    modified["変更あり<br/>初期状態に戻す 活性"]
    comparing["比較中<br/>プレビューを左右に分ける"]
    back["ca_lst / cc_gnr"]
    initial -- スイッチか値を変える --> modified
    initial -- 比べる --> comparing
    modified -- 比べる --> comparing
    comparing -- 比べるのをやめる --> modified
    comparing -- 別のチップを選ぶ --> modified
    modified -- 初期状態に戻す --> initial
    comparing -- 初期状態に戻す --> initial
    initial -- 戻る --> back
    modified -- 戻る 設定は捨てる --> back
    comparing -- 戻る 設定は捨てる --> back
```

状態とイベントの型は docs/design/functions/demo-engine.md の「DetailState」「イベント」。比較中にやめたときは、値が最初と同じなら「初期状態」として扱う（`isModified` で判定）。見た目を持たない Widget は「別のチップを選ぶ」で比較をやめない（比較中のまま値を変えられる）。見た目を持たない Widget は、比較の開始・終了と「初期状態に戻す」で計測をやり直す（build の回数とログを空にしてデモの木を組み直し、どの子も「build 1 回」から数える）。チップを選び替えるだけでは変更にしない。

## 基本方針

- 収録データは同梱。通信するのは「公式ドキュメントを開く」で外部のブラウザを開くときだけ
- プロパティを変えたら、プレビュー・チップの値・コードの帯にすぐ反映する（反映の待ちを見せない）
- プレビューの中は収録する Widget の見た目のまま。アプリの UI の色・影を重ねない（design-system の原則1）。方眼はカードの地にだけ描く
- 一度に触るのは 1 つのプロパティ（編集パネル）。全体の状態はチップの列で見渡す

## 実装時の考慮事項

- スクロール・固定領域・キーボード表示時: App Bar・プレビュー・コードの帯・チップの列は固定し、編集パネルの中身がはみ出すときはパネルの中でスクロールする。文字の入力欄でキーボードが出たら、プレビューの高さを縮めて（最小は画面の高さの約 2 割）入力欄が隠れないようにする
- アニメーション: 値の変化そのものの動き（`AnimatedContainer` など）は Widget のまま。アプリ側で足すのは、比較の 1 枚 ↔ 左右の切り替え（200ms 程度のフェード）と、編集パネルの中身の切り替え（150ms 程度のフェード）だけ。端末の「視差効果を減らす」が ON なら即時
- OS 別の対応: 戻る操作は OS の標準。Cupertino の Widget も Android でそのまま表示する（PRD）
- 動的コンテンツ: 型の名前が長いとき（例: `MainAxisAlignment`）は折り返す。コードは折り返さず横スクロール（帯は末尾を省略）
- 文字サイズの拡大: OS の設定に Flutter が合わせる（`MediaQuery.textScaler`）。この画面で個別の対応はしない
- タブレット: 1 カラムのまま、本文の最大幅を 640 にして中央に置く
- アクセシビリティ:
  - 読み上げの順は 戻る → 題 → 説明 → 初期状態に戻す → プレビュー → コードの帯 →（ログの帯）→ 仲間のタブ → チップ → 編集パネル
  - 回数の印は「読む子、build 4 回」と読む。光る動きは読み上げない。ログの帯は「ログ、12 件、最新: 読む子を build。ボタン」と読む
  - タブは「大きさ、ON が 2 件。ボタン」と読み、読み上げのタップ操作で押せる。同時に使えない組の知らせはライブリージョンで読み上げる。薄いチップも名前と値は同じように読む
  - チップは「padding、16、選択中。ボタン」「width、既定。ボタン」のように読む
  - 比較のラベルは文言とアイコンで示し、色だけに頼らない。比較中のプレビューは「付けた、color、瑠璃」「付けない」と読む
  - 仕切りはドラッグのほかに、読み上げの調整操作（`Semantics` の increase / decrease）で 10% ずつ動かせる
  - スイッチは「padding を付ける、オン」と読む。スライダーは今の値を読む。Alignment のマスは「topLeft、ボタン」と読み、選んだものは「選択中」
  - アイコンだけのボタン（説明・初期状態に戻す・拡大）にラベルを付ける
  - プレビューの中は収録する Widget の Semantics のまま（アプリは足さない）
