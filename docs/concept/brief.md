> **要約**
> - 結論: Flutter の Widget を、プロパティを切り替えて触り、付けた／付けないを並べて比べられる iOS / Android アプリを作る
> - 影響: Flutter の実装知識を作り直すこと（12ヶ月の目標③）と、成果物を残すことを同時に満たす

## 2. 提供価値・どう変えるか
- Before: 挙動を思い出すたびに、ドキュメントを読み、試しのコードを書いて確かめている
- After: アプリを開けば数十秒で「これを付けるとこう変わる」を目で見て思い出し、そのまま手を動かせる

## 3. なぜ自分がやるか（思想との整合）
- 合っている点: future-vision.md の「次の12ヶ月」③（ネイティブ / Flutter の実装知識を作り直す）、values.md の「彩り」の定義（開拓の余地・自分で試せる・幅が広がる）
- ズレ: values.md の「理想を追って挫折することが多い」と「リリースまでに全部」が重なる。中学英文法アプリ（最優先）と時間を取り合う
- self-proxy は使っていない（メインでメモを読んで照らした）

## 4. コア機能の候補
1. A. プロパティのプレイグラウンド（触る）: トグル・スライダー・選択で値を変えると、その場で反映される
2. B. 付けた／付けないの比較表示（比べる）: 2つを並べて差を見せる
3. C. 目的からの逆引き・D. コードの表示とコピーは補助（PRD で要否を決める）
- 選んだ案: A＋B を一体にしたもの。作らない案（公式ドキュメントと DartPad）では「触らないと忘れる」が解けない。Web 版は「手元のネイティブアプリ」という希望から外れる（同じコードから後で出せる）

## 6. 差別化 / 既存の代替手段
- 代替手段: 公式の Widget カタログ（画像中心）、API ドキュメントの DartPad サンプル（ブラウザで1つずつ）、Widget of the Week の動画。昔の公式 Flutter Gallery アプリは今はメンテナンスされていない
- 優位: 手元のネイティブアプリで、プロパティを自分で切り替えて比べられる。見た目を持たない Widget まで含めて、ジャンル別に体系立てて収録する

## 9. 最大の未検証リスク
- 全部収録してからリリースする方針と、リリース前に失速する傾向。本人の判断で締切は置かない
- 保守の量: Flutter の安定版リリースごとに、全 Widget の非推奨化・変更を見直す必要がある
- 見た目を持たない Widget のデモ: InheritedWidget などの「付けた／付けない」をどう見せるか（再ビルドの回数を出す、など）が未設計
- ストア審査: 参照用アプリとして Apple の 4.2（最低限の機能）に触れないか
- 未検証のイシュー: 「どのくらい困っているか」（頻度）、他の人（初心者・デザイナー）にも役立つか
