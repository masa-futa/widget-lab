# ADR-0004: 一覧をジャンルから入る2段にし、詳細をチップと編集パネルにする

> **要約**
> - 結論: 一覧は「ホーム（検索＋ジャンルのタイル）→ ジャンル画面（見本つきの行）」の2段にする。詳細はタブをやめ、プロパティのチップの列と、選んだ1つを大きく触る編集パネルにし、比べるはプレビューを左右に分ける
> - 影響: ca_lst（ホーム画面に作り直し）・cc_gnr（新しい画面）・cb_dtl（作り直し）、demo-engine.md の CatalogState・DetailState・コード生成、テストケース
> - お願い: なし（2026-10-28 オーナーが Figma の案B と詳細 v2 を選んだ）

## ステータス
承認済み（2026-10-28）

## 背景
PR #5・#6 で、一覧（ジャンルの見出しで区切った1本のリスト）と詳細（プレビュー＋「操作・説明・コード」のタブ）を作った。Figma に書き起こして見比べたところ、オーナーから次の指摘があった。

- 一覧: 区切りがなく情報が多すぎる。件数の見せ方を工夫したい。全部収録すると 242 件になり、1本のリストでは長すぎる
- 詳細: プロパティの行が下に並ぶだけで、操作しやすい構成にしたい。操作した結果がコードにどう反映されるかが見えにくい

Figma（https://www.figma.com/design/W9DAjjGAmMzNhnCQu0BLo7/Widget-Lab?node-id=3-2）で一覧の案を 3 つ（プレビューつきの行・ジャンルから入る・ジャンルごとの横の列）、詳細の案を 3 つ（コンパクトな行・指定中を上に・チップと編集パネル）描いて比べた。

## 決定
- 一覧はジャンルから入る2段にする。ホームは検索とジャンルのタイル（件数・名前・代表の Widget 名。「デザインシステム」と「基本の Widget」の段）。ジャンル画面は、Widget を最初の値で組み立てて縮めた見本つきの行。検索の結果はホームでタイルの代わりに同じ行で出す（重ねず、名前の ABC 順）
- 詳細はタブをやめる。上にプレビュー（方眼の地・×1 / ×2）とコードの帯（選んでいるプロパティの 1 行）、その下にプロパティのチップの列（名前と今の値）、下半分に選んだ1つを大きく触る編集パネル（型ごとの操作。Alignment は 3×3、色は大きな色見本）。説明は App Bar の ⓘ からシート、コードの全文は帯からシート（既定から変えた行に印）
- 比べるは、選んでいるプロパティについて、プレビューを左右に分けて仕切りをドラッグする
- 詳細を開いたときは、最初の ON のプロパティを選んでおく
- ガイド（子の範囲の点線）・よく使う値・「試してみる」は後の段に回す
- 文字の拡大は OS の設定に Flutter が合わせる。画面ごとの個別の対応はしない

## 選ばなかった案
| 案 | 選ばなかった理由 |
|---|---|
| 一覧: 1本のリストに見本つきの行（案A） | 画面は増えないが、242 件を1本で流すと全体の地図が見えない |
| 一覧: ジャンルごとの横の列（案C） | 眺めるには楽しいが、件数の多いジャンルの全件を探すには向かない |
| 詳細: 行をコンパクトにする（案A） | 縦に並べる構成のままで、操作の改善が小さい（オーナー「もうちょっと凝って」） |
| 詳細: 指定中の行を上にまとめる（案B） | スイッチを押すと指の下で行が別のまとまりへ動き、続けて触るときに押し間違えやすい |
| 詳細: 比べるを上下の 2 枚にする（今の実装） | 上下だとプレビューが半分の高さになる。左右の分割なら同じ位置で境目を動かして違いを見られる |

## 結果
- 画面は 3 枚（ca_lst ホーム・cc_gnr ジャンル・cb_dtl 詳細）。遷移はホーム → ジャンル → 詳細と、ホームの検索の結果 → 詳細
- `Genre` に段（`group`）と一言の説明（`description`）を足す。`CatalogState` は `groups`・`results` に、`DetailState` に `selected` を足す。`CodeGenerator` は行ごと（`CodeLine`）に返す
- 拡大と比較の仕切りの位置は、画面の中だけの状態として StatefulWidget に持つ
- 実装は一覧（ホーム・ジャンル画面）と詳細 v2 の 2 つの PR に分け、並列で進める
- 見直すきっかけ: 全件を収録して使ってみて、ジャンルの段を行き来する手間が気になったとき
